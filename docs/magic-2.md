# Магия 2.0 — как сделать магию living-wand живой, стабильной и изучаемой

Документ — результат свободного изучения проекта: диагноз, идеи по самой магии и то, что из этих идей уже воплощено в коде ветки `claude/magic-stability-refinement-tdaorb`. Код — следствие идей, а не наоборот.

---

## 0. Коротко

1. **Пайплайн был цепочкой жёстких решений без обратной связи.** Ошибка на входе (OCR) усиливалась на каждом шаге. Единственная петля обучения была замкнута сама на себя. Главная причина «чувствительного OCR» — сеть училась на картинках, которые выглядят совсем не так, как штрихи в игре.
2. **Магия — это язык.** Заклинание — фраза: *чем* (стихия) + *на что* (домен) + *куда/кому* (вектор, ссылка) + *как* (масштаб, модификатор) + союзы (рёбра). Игрок должен уметь прочитать своё заклинание вслух.
3. **Магия — это физика свойств.** Заклинание не «наносит 12 урона», а меняет свойства мира: жар, влагу, свет, жизнь, прочность, движение, ход времени, волю. Последствия решает движок. Это и есть ответ на вопрос «что писать в API».
4. **Язык надо выучить.** Игрок не получает таблицу из 30 рун. Он начинает с шести слов, а остальные узнаёт в снах палочки и в экспериментах, ведя собственный словарь.
5. **Один субстрат — много ремёсел.** Заклинание, зелье и зачарование — один и тот же граф, одна алгебра и одна программа для движка. Меняются только «слова», «сосуд» и «доставка».
6. **Агенты — это автоплейтест.** Поиск по пространству заклинаний находит доминирующие стратегии и эксплойты раньше игроков. Первая же находка — «спагетти-эксплойт» — закрыта механикой «круг — сосуд».

## 1. Диагноз: почему было нестабильно

### 1.1 Цепочка жёстких решений

```
штрихи → кластер (80 px) → ОДНА метка OCR → связи по расстоянию → SpellFormer → теги → механика
```

Каждый шаг принимал необратимое решение и передавал дальше только его. Одна неверно прочитанная руна меняла граф целиком. Связи «по расстоянию» (< 150 px — смешение, < 300 px — направленная) превращали случайный сдвиг руны в другое заклинание и создавали клики из MUTUAL, то есть случайные тройные комбо.

### 1.2 Замкнутая петля обучения

AdaptiveOCR «учился у SpellFormer». Но граф, который читает SpellFormer, построен *из предсказаний OCR*: модель подтверждала то, что OCR уже сказал. Хуже того, правка срабатывала, если *другая* руна в заклинании была стихией. Глиф `amplify` переучивался в `fire` только потому, что рядом был нарисован огонь. Вдобавок `_fine_tune` падал (заплатка FIXIT), а в «замороженном» режиме BatchNorm продолжал менять статистики и тихо сдвигал все предсказания.

### 1.3 Обучение и игра видели разные миры

Синтетические руны рисовались с независимым дрожанием *каждого пикселя* (σ 1.5–4 px) — получались облака, а не линии. В игре сеть видела чистые линии, отмасштабированные до 80% кадра, а точки (клик) вообще выбрасывались. Замер на 1240 «человеческих» рисунках (вариации, которых не было в обучении, `tools/ocr_bench.py`):

| | старый путь | новый путь |
|---|---|---|
| точность | 56.9% | **96.2%** |
| top-3 | 80.1% | 99.7% |
| метка меняется при повторном обводе той же руны | **35.9%** | 3.7% |
| ошибка калибровки (ECE) | 0.277 | 0.025 |
| уверенность, когда ошибается | 0.76 | 0.84* |

\* Новая сеть ошибается редко, а в целом её уверенность честная (ECE 0.025). Старая была уверена (0.76), даже когда ошибалась на каждом втором рисунке.

**36% перескоков при повторном обводе — это и есть «слишком чувствительный OCR».**

### 1.4 Ошибки в самой магии

- `weaken`, `hold` и `dispel` работали как `amplify`: все модификаторы попадали в ветку `magnitude > 0`. Рецепт «тёплая постель» (ослабленный огонь) на деле был *усиленным* огнём.
- Порядок рисования менял результат: другие токены, другое вычисление алгебры, другой хэш кристалла.
- `EdgeType` и `Operator` нумеровались по-разному. MUTUAL превращался в REVERSE, поэтому проверка «парадокса времени» не срабатывала никогда. Когда маппинг починили, выяснилось, что она ещё и падала с IndexError.
- Утечка силы у открытого круга применялась до того, как сила была посчитана, то есть ничего не делала.
- Свежая палочка добавляла к выходу SpellFormer случайный шум (до того, как у неё появился хоть какой-то опыт).

### 1.5 Концептуальная дыра: зачем сеть?

SpellFormer учится подражать алгебре и поэтому не может стать лучше алгебры: в лучшем случае он шумный кэш. **У сети должна быть работа, которую алгебра сделать не может.** Варианты:

- оценивать заклинания с рунами, которых в алгебре нет (сигилы игрока, §4.4);
- учиться у мира: дообучаться на *исходах* из движка, а не на алгебре (§4.1);
- давать интерполяцию для «дикой магии», когда руна прочитана нечётко (§2.6).

Пока таких задач нет, правило такое: **структуру решают правила, нюанс — сеть** (§2.5).

## 2. Принципы новой магии

### 2.1 Заклинание — фраза

| роль | руны | вопрос |
|---|---|---|
| сила | огонь, вода, воздух, земля, свет, тьма | *чем?* |
| домен | тело, разум, материя, пространство, время, жизнь | *на что?* |
| вектор | внутрь, наружу, вверх, вниз, сквозь, вспять | *куда?* |
| масштаб | точка, поток, волна, всё | *какой формы?* |
| модификатор | усиление, ослабление, удержание, развеяние | *как?* |
| ссылка | здесь, там, сам, цель | *кому / где?* |
| рёбра | → ═ ⋯ ?→ ¬ ↻ ⊣ | и / смешать / затем / если / не / снова / только |

Следствия:

- **Игрок читает заклинание вслух.** Под кругом показывается фраза: «огонь → наружу → цель».
- **Грамматическое автосвязывание.** Если связи не нарисованы, палочка связывает руны по смыслу: модификатор, масштаб и вектор питают ближайшую силу или домен; сила и домен смешиваются, если стоят рядом; ссылка принимает поток. Это совпадает со всеми рецептами в `combos_recipes.json` (`hold → fire`, `fire → here`, `outward → air`).
- **Ссылка задаёт намерение.** `цель`/`там` — враждебное, `сам` — поддержка, `здесь` — бытовое, обращение к окружению. Свеча (`огонь, точка, удержание, здесь`) теперь *греет и светит*, а не наносит урон огнём вокруг заклинателя.

### 2.2 Магия — физика свойств (ответ «что писать в API»)

Таблица «огонь = урон» — это та самая мёртвая таблица правил, от которой проект уходит. Магия должна менять **свойства мира**, а последствия — возникать:

| свойство | что значит | пример последствия в движке |
|---|---|---|
| heat | температура | дерево воспламеняется, лёд тает |
| moisture | влага | огонь гаснет, растения растут |
| motion | напор | отбрасывание, ветер |
| solidity | прочность | стена, броня, трещины |
| light | свет / тьма | видимость, ослепление |
| vitality | жизненная сила | лечение / увядание |
| will | состояние разума | ясность, страх, морок |
| position | сдвиг пространства | телепорт, искривление |
| timeflow | ход времени | замедление, ускорение, откат |

Каждый канал вносит дельты (`data/fields.json`). Огонь: жар +1.0, свет +0.3, влага −0.3. Отрицание переворачивает знак. Так устроены «живые» системы вроде химии BotW и Noita, где правила взаимодействия задаёт материал, а не заклинание.

Глаголы (`damage`, `heal`, `shield`…) остаются, но как **удобный слой** для движков без системы материалов. Оба слоя едут в одной программе (§6).

### 2.3 Мир влияет на магию

На вход каста идёт контекст: погода, время суток, место (`data/environment.json`). Дождь гасит огонь (×0.6), ночь кормит тьму (×1.4), лей-линия усиливает всё, но делает его нервным (стабильность ×0.8), на кладбище жизнь слабеет. Одна и та же руна в разных местах ведёт себя по-разному. Это сразу геймплей (выбирай место и время) и защита от «решённой» меты.

### 2.4 Круг — сосуд

У круга есть ёмкость: `7 × радиус × (0.6 + 0.4 × чистота рисунка)`. Нагрузка — руны плюс половина рёбер. Перегрузка бьёт по стабильности и силе и даёт риск отдачи. Механику нашёл не дизайнер, а **агент** (§8): лучшими заклинаниями оказывались «спагетти» из 7–8 рун, где всё соединено со всем, потому что каждое ребро — ещё один бесплатный множитель. После ввода сосуда лучшие заклинания — 3–5 рун.

Та же идея обобщается на ремёсла: сосуд — это колба алхимика или материал зачарованного предмета (§5).

### 2.5 Структуру решают правила, нюанс — сеть

Компилятор (`src/wand/actions.py`) берёт из графа и алгебры **дискретное**: кому, как доставить, какие глаголы. Модель и личная палочка двигают **непрерывное**: силу, площадь, длительность, цвет. Небольшое дрожание сети может сделать огненный шар горячее, но никогда не превратит его в лечение. Режим переключается параметром `authority = algebra | blend | model`. В программу пишется, насколько модель согласна с алгеброй (`provenance.agreement`): расхождения — это или дыры в данных, или кандидаты в «дикую магию».

### 2.6 Неточность — ресурс, а не ошибка (предложение)

Следующий шаг после починки OCR: **мягкие токены**. Неуверенно прочитанная руна входит в заклинание смесью эмбеддингов (70% огонь + 30% усиление). Трансформер это поддерживает естественно: токен — это просто вектор. Результат — «дикая магия»: непредсказуемая, но не сломанная. Чистота штриха становится навыком (контроль и стабильность), а не воротами «распознал / не распознал». Пайплайн тогда передаёт между стадиями **распределения, а не решения** — это лечит каскадные ошибки в корне.

Уже сделано по этому направлению: неуверенные руны подсвечиваются, игрок колесом мыши выбирает другое прочтение, и именно это подтверждение становится доверенной меткой для дообучения на его почерке.

## 3. Как игрок учит язык магии

Игроку не хватает словаря: он не знает даже базы. Выдать ему алфавит — значит превратить игру в справочник. Заставить угадывать вслепую — значит дать шум. Поэтому язык преподаёт палочка (`src/wand/dream.py`).

### 3.1 Словарь игрока

- Игрок начинает с **шести слов**: огонь, вода, здесь, сам, цель, наружу.
- Незнакомые руны распознаются, но показываются как «?». Палочка понимает их глухо: сила снижена.
- **Слово через опыт.** Незнакомая руна, встреченная в трёх заклинаниях наяву, выучивается «на ощупь».
- **Заметки.** После каждого каста словарь записывает, что делало заклинание с каждой своей руной. Заметки корреляционные, как у настоящего экспериментатора: сначала «смутно», после 3 кастов «похоже», после 8 «уверенно». Например: «огонь — уверенно: жар, свет, сухость; ранит, меняет тепло».

### 3.2 Сон как пространство изучения

Сон — безопасная лаборатория: касты бесплатны, отдачи нет, опыт не тратится.

1. **Палочка засыпает** и обучается на прожитом дне (опыт из исходов, §4.1).
2. **Видение.** Палочка ищет заклинание, которое игрок сотворил бы, *зная на одно слово больше*. Используется та же машинка поиска, что и в инструментах. Игрок видит только *эффект*:
   > «Ты видишь алые языки пламени, индиговые кольца. Это вспыхивает разом и ранит и переносит — кого-то вдали. Ты чувствуешь: жар, сдвиг, свет.»
3. **Попытки с подсказкой по аспектам.** Каждая попытка получает «теплее/холоднее» по частям смысла:
   > «Горячо. суть («ранит») — да; движение — да; на кого — да; жар — да; свет — да; сдвиг — нет»

   Игрок узнаёт не «правильно/неправильно», а **за что отвечает каждая часть его заклинания**. Это и есть обучение языку.
4. **Подсказки по уровням (H):** незнакомый знак → сколько было знаков и какие знакомые → связи.
5. **Разгадка** — новое слово в словаре. Заклинание засчитывается, если *эффект* совпал, даже если рецепт другой: сон судит смысл, а не буквы.

### 3.3 Куда это развивать

- **Палочка-исследователь.** Видения выбираются там, где у игрока белые пятна в заметках («ты ни разу не видел, что делает тьма с телом»).
- **Сны-загадки посложнее.** Две незнакомые руны, или знакомые руны в незнакомом сочетании (каталог открытий подсказывает, что ещё не найдено).
- **Кошмары.** Видение нестабильного заклинания: научись его *не* творить, то есть распознай, что делает его опасным.
- **Общие сны** в мультиплеере: двое видят одно видение и решают его, складывая свои словари.

## 4. Палочка как персонаж

Раньше опыт был кнопками 1–6, XP-банки ничего механически не делали, а адаптер учился на нулевом векторе. Теперь (`src/wand/session.py`):

### 4.1 Опыт из исходов

Движок сообщает, что *на самом деле* произошло: попал ли снаряд, сколько вылечил, сколько целей задел, была ли отдача (`Outcome`). Это событие опыта:

- полюса — из каналов, которые программа реально задействовала;
- вес растёт с весом последствий и **падает при повторении** того же заклинания: опыт вознаграждает исследование, а не гринд;
- во сне адаптер учится на настоящих выходах SpellFormer тех кастов, которые дали опыт.

### 4.2 Мастерство видно и понятно

- **Почерк.** Частые руны палочка читает охотнее: ниже порог принятия, меньше «неуверенных». Подтверждения игрока весят вдвое.
- **Стабильность.** Знакомые руны дают до +0.08 стабильности.

### 4.3 Подписи палочки

Уровни полюсов открывают *видимые* изменения заклинаний (`data/signatures.json`), а не скрытый дрейф весов:

| полюс, уровень | подпись | что меняется |
|---|---|---|
| стихия 3 | Пыл | урон +15% |
| стихия 5 | Разрыв | снаряды взрываются при попадании |
| биология 3 | Прижигание | урон возвращает 20% как лечение |
| биология 5 | Чистое исцеление | лечение снимает яды и горение |
| ментал 3 | Ясный ум | стабильность +0.05, статусы дольше |
| пространство 3/5 | Дальнобой / Стремительность | дальность, скорость снарядов |
| время 3 | Терпение | длительность +30%, заряд дольше |
| трансформация 3 | Рука мастера | трансформация +20%, дешевле |

Огненный шар целителя прижигает и лечит, огненный шар воина взрывается. Одна и та же фраза у разных людей звучит по-разному, и игрок *понимает почему*.

### 4.4 Кристаллы → сигилы (предложение)

Сейчас кристаллизация требует 500–5000 кастов, а токены кристаллов никогда не попадают в токенизатор. Предлагается иное. Освоенное заклинание (~20 удачных кастов) игрок **сворачивает в собственный знак**: рисует новый глиф 3–5 раз. OCR запоминает его по прототипу (эмбеддинг предпоследнего слоя, ближайший сосед). Сигил становится новой руной и используется в больших заклинаниях. Так алфавит растёт вместе с игроком, а у SpellFormer появляется работа, которую алгебра не может сделать: оценивать фразы с этими новыми словами (§1.5).

## 5. Ремёсла на том же субстрате

Алхимия и зачарование — не отдельные системы. Это тот же граф, та же алгебра и тот же компилятор (`src/wand/craft.py`):

| | заклинание | алхимия | зачарование |
|---|---|---|---|
| слова | руны | «природы» ингредиентов (маленькие подграфы рун) | руны |
| сосуд | нарисованный круг | колба (глина 6, стекло 8, хрусталь 11) | материал предмета |
| доставка | из векторов и ссылок | выпить / бросить (`consume` / `splash`) | вшить с триггером (`imbue`) |
| мир | погода, время, место | (котёл) | сродство материала |

**Алхимия.** Ингредиент несёт свою природу: сердечный корень = тело═жизнь, сера = огонь═тьма (`data/ingredients.json`). Варка смешивает природы. Шаги — это руны и рёбра: *нагреть* добавляет огонь, *настоять* — удержание и время, *перегнать* — воздух через «только», *дать перебродить* — жизнь через «снова». Переполненный горшок портит варево: качество падает до нуля.

**Зачарование.** Сосуд — предмет. Серебро любит свет (×1.4) и не любит тьму, железо гасит магию (×0.85), но успокаивает её, обсидиан кормит огонь и тьму (`data/materials.json`). Срабатывание: при ударе, при применении, пока надето, когда ранен носитель. Если заклинание легко помещается в материал, оно держится постоянно, если впритык — выгорает за несколько зарядов.

**Главное следствие:** всё, что игрок узнал об огне и земле у круга, верно в котле и в кузнице. Сны, словарь, исследователь и API работают для зелий и предметов без изменений.

Что ещё естественно ложится на субстрат:

- **ритуалы** — несколько магов соединяют свои графы в общий круг, ёмкость суммируется;
- **руны-ловушки** — зачарование места (материал = почва или камень, триггер = вошёл в зону);
- **свитки** — отложенный каст: программа сохраняется и исполняется позже;
- **контрмагия** — `dispel` и сравнение программ: чем ближе контрзаклинание к исходному, тем сильнее гасит.

## 6. API для движка

### 6.1 Что внутри `SpellProgram`

```
SpellProgram  (schema 1.0, JSON)
  target     self · target · point · caster_area           — кому/где
  delivery   instant · projectile · beam · zone · aura · touch · consume · splash · imbue
  shape      single · sphere · cone · line · ring · wall    — форма зоны
  fields[]   {property, delta, duration, falloff, trigger}  — ФИЗИКА: что меняется в мире
  ops[]      {verb, channel, amount, duration, period, trigger, params}
             — ГЛАГОЛЫ (удобный слой): damage, heal, shield, status, push, pull, move,
               timescale, light, obscure, transform, grow, temperature, cleanse, dispel,
               reveal, communicate
  phases[]   charge → release → travel → impact → linger    — таймлайн для анимации и звука
  visual     palette, core/glow color, motions, signatures, intensity, turbulence
  risk       backfire_chance, backfire ops, reasons         — движок сам бросает кубик
  cost, cast_time, cooldown
  provenance алгебра против модели, agreement, сосуд, контекст, подписи, ремесло
```

Принципы: числа нормализованы (≈0..1), **баланс в единицах движка** (урон за единицу, метры, секунды) — дело движка. Программа детерминирована, исполнение стохастично (`roll_backfire`). Схема — `GET /schema`.

### 6.2 Три направления

- **Вход:** штрихи (`POST /cast/strokes`) или граф (`POST /cast/graph`) плюс **контекст мира**.
- **Выход:** программа (оба слоя: поля и глаголы) плюс визуальная спецификация.
- **Обратная связь:** `POST /outcome` — что произошло на самом деле. Это опыт палочки, а в перспективе — данные для дообучения модели на физике *мира*, а не алгебры.

Плюс ремёсла (`/brew`, `/enchant`, `/crafts`) и обучение языку (`/dream`, `/dream/hint`, `/dream/attempt`, `/lexicon`). Транспорт — HTTP (`python tools/serve.py`) или stdio JSON-lines (движок запускает процесс сам).

### 6.3 Пример (Godot)

```gdscript
var http := HTTPRequest.new()
add_child(http)
http.request_completed.connect(_on_cast)
var body := {"graph": {"nodes": [{"name": "fire"}, {"name": "outward"}, {"name": "target"}],
                       "edges": [["fire", "outward", "DIRECT"], ["outward", "target", "DIRECT"]]}}
http.request("http://127.0.0.1:7777/cast/graph", ["Content-Type: application/json"],
             HTTPClient.METHOD_POST, JSON.stringify(body))

func _on_cast(_r, _code, _h, raw):
    var p = JSON.parse_string(raw.get_string_from_utf8())["program"]
    for f in p["fields"]:          # физика: пусть материалы решают
        world.apply_field(f["property"], f["delta"], p["shape"], p["target"])
    vfx.play(p["visual"], p["phases"])
```

`vfx.py` в репозитории — пример такого потребителя на pygame: он не знает ничего, кроме программы и штрихов игрока.

## 7. Визуальный язык: «светящаяся тушь»

- **Штрихи игрока — фитиль.** Во время заряда руны разгораются цветами своих стихий, а на выпуске сгорают в искры. Почерк игрока становится формой эффекта: двух одинаковых огненных шаров не бывает.
- **Таймлайн из программы:** заряд (искры стягиваются в круг) → выпуск (вспышка, кольцо, тряска экрана по силе) → полёт (ядро со шлейфом) → удар (вспышка, ударная волна) → затухание (зона, аура или луч).
- **Язык движения по каналам:** огонь поднимается и мерцает, вода падает, воздух кружит, земля пульсирует, свет разлетается, тьма схлопывается.
- **Подписи:** пар, шторм, лава, кристалл, вспышка, затмение, развеяние — у каждой свой рисунок.
- **Нестабильность видна:** частицы дрожат пропорционально `turbulence`, из разрыва открытого круга сыплются искры, у перегруженного круга трескается кольцо, отдача схлопывается красно-чёрной воронкой.
- **Сон** — другая палитра (индиго, звёзды), касты во сне призрачно-голубые.

Дальше, уже в движке: шейдер искажения воздуха для жара, bloom, звук по фазам таймлайна, обводка руны по траектории пера в реальном времени.

## 8. Инструменты: агенты как автоплейтест

Пространство заклинаний дискретное и многомерное, и агент с деревом поиска картирует его в тысячи раз быстрее игрока. Это риск: мету «решат» по вики. Но это и инструмент: можно увидеть это заранее.

- **`tools/explore.py`** — MAP-Elites: лучшее заклинание в каждой нише «глагол × доставка × размер». Отчёт показывает доминирующие руны, мёртвые глаголы, выбросы «сила на руну», кривые стака, покрытие каталога открытий и 2-D атлас (PCA).
- **Инварианты баланса как тесты:** `--check` возвращает код 1, если медиана размера лучших заклинаний > 5 рун, покрытие < 60%, больше двух мёртвых глаголов или есть абсурдный выброс. Запускай после каждой правки `data/*.json`.
- **Обратный поиск** — `--find "damage projectile piercing stable"` → `земля═огонь + сквозь…`. Этот же поиск генерирует видения во снах.
- **`SpellEnv`** — среда в стиле gym (reset/step) для RL. Наблюдение — токены SpellFormer, награда — любая цель.
- **`tools/ocr_bench.py`** — проверка OCR на «человеческих» рисунках: точность, перескоки при повторном обводе, калибровка, частые путаницы.

Что агенты уже нашли:

| находка | статус |
|---|---|
| «спагетти»: всё соединено со всем, рёбра бесплатны | закрыто сосудом (§2.4) |
| ITERATE между рунами дёшев и часто встречается у лучших заклинаний | открыто: дать ITERATE цену в нагрузке сосуда |
| стак `amplify` растёт до 4 штук, потом стабильность его обрушивает | норма |
| `earth ↔ space` путаются в OCR (квадрат и ромб отличаются только поворотом) | открыто: перерисовать один из знаков |
| стак `flow` не меняет силу, только длительность | норма: поток — про время, а не про мощь |

## 9. Дорожная карта

По пользе для магии:

1. **Мягкие токены и дикая магия** (§2.6) — убирает последнюю жёсткую границу в пайплайне.
2. **Сигилы вместо кристаллов** (§4.4) — алфавит растёт с игроком, у сети появляется своя задача.
3. **Сид мира** — каждый мир слегка переставляет множители синергий (±20%). Знание нельзя нагуглить, его нужно добыть; исследователь меряет, за сколько кастов мир «взламывается».
4. **Дообучение SpellFormer на исходах из движка** — ground truth становится физикой мира, а не алгеброй.
5. **Почерк на прототипах** — личная адаптация OCR через ближайших соседей в пространстве признаков, без дообучения головы.
6. **Баланс по находкам агентов:** цена ITERATE, редизайн знака `earth` или `space`, роль `flow`.
7. **Ритуалы, свитки, руны-ловушки, контрмагия** (§5) — всё на том же субстрате.

| `src/wand/craft.py` | алхимия и зачарование |
| `src/wand/explore.py` | MAP-Elites, обратный поиск, отчёт по эксплойтам, `SpellEnv` |
| `data/verbs.json`, `fields.json`, `environment.json`, `signatures.json`, `ingredients.json`, `materials.json` | всё, что правит дизайнер, — без кода |

```bash
python tools/train_ocr.py          # новый чтец рун → data/ocr_symbolnet_v2.pt (~15–25 мин CPU)
python train.py                    # SpellFormer под исправленную алгебру (старые веса устарели)

python tools/explore.py --check    # автоплейтест баланса
python -m pytest tests             # тесты
```

> Старые `data/spellformer.pt` и `data/ocr_symbolnet.pt` обучены на прежней алгебре и прежних картинках. Их стоит переобучить: алгебра поменялась (модификаторы, порядок), а токены теперь канонические.
